NODES — 5 PROCESSING NODES, 1 CONDITIONAL EDGE

1. ProductClassifierNode
Takes the raw product description and extracts the HS code and product attributes. Returns the top candidate HS code, up to two alternatives if ambiguous, and a classification confidence score. All three candidates are carried forward in state.

2. ComplianceCheckNode
Takes the HS code and destination country from state and checks legality against the compliance database. Returns compliance status (clear, restricted, or blocked), the sources it checked, and a compliance confidence score. If sources conflict, it records both findings and marks compliance confidence as low.

3. DutyCalculatorNode
Takes the confirmed HS code and destination country and retrieves the applicable duty rate, VAT, and any additional levies. Where the rate is conditional on product origin, it captures both bounds. Returns the duty rate, the source it pulled from, and a duty confidence score.

4. ConfidenceGate (Conditional Edge)
This is a conditional edge function, not a processing node. It reads the three confidence scores from state — classification, compliance, and duty, then computes a weighted overall confidence score. If the score is above the defined threshold, the graph routes to ResultAssemblerNode. If below, it routes to HumanReviewNode. The threshold and score weightings are stored in graph config.

5. HumanReviewNode
This is where the graph pauses. LangGraph's interrupt() is called here, which serializes the full graph state and writes it to a durable checkpointer — PostgreSQL or Redis depending on deployment. The graph terminates at this point with a PAUSED status. It does not block a thread. A notification is sent to the human reviewer containing the extracted HS code, compliance status, the conflict or ambiguity that triggered escalation, and the escalation reason from state. The graph waits indefinitely until the human submits their resolution via the API.

6. ResultAssemblerNode
Packages the final structured result for the checkout layer. Combines the HS code, compliance status, duty rate, and landed cost. Uses the upper bound of any duty range carried in state. If the result passed through human review, the resolved fields are flagged as human-verified.


STATE STRUCTURE

The state is a TypedDict passed through every node. Key fields:

- product_description: raw input string
- hs_code: primary extracted code
- hs_alternatives: list of up to two alternatives with confidence scores
- hs_confidence: float
- product_attributes: dict
- destination_country: string
- compliance_status: enum — clear, restricted, blocked, conflicted
- compliance_sources: list of sources with individual findings
- compliance_confidence: float
- duty_rate: float or range tuple
- duty_source: string
- duty_confidence: float
- overall_confidence: float, computed at ConfidenceGate
- escalation_reason: string
- human_resolution: dict — populated on resume, contains verified hs_code and any notes
- human_resolved_at: timestamp
- hs_code_changed: boolean — set by HumanReviewNode on resume by comparing human_resolution.hs_code against the original hs_code in state
- landed_cost: float, computed at ResultAssembler
- final_confidence: float
- status: enum — processing, paused, resumed, complete
- thread_id: string


WHERE THE CONFIDENCE GATE SITS

After DutyCalculatorNode, before ResultAssemblerNode. Implemented as a conditional edge. Returns either "assemble" or "escalate" as the routing decision.


HOW THE HUMAN-IN-THE-LOOP PAUSE WORKS

LangGraph's interrupt() halts the graph at HumanReviewNode and writes full state to the checkpointer under the thread_id. Nothing is held in memory. When the human submits their resolution, the back-office API calls graph.update_state() to inject the human_resolution into stored state, then calls graph.invoke() with the same thread_id to resume. LangGraph retrieves the checkpointed state, skips all previously completed nodes, and continues forward.


HOW DETERMINISM IS GUARANTEED AFTER RESUME

No previously completed node re-runs on resume. The checkpointed state is the source of truth. The graph is not re-fetching duty rates, re-checking compliance, or re-classifying the product. It is completing a computation already in progress, with the human's resolution injected into frozen state.

If external data changed during the pause — a tariff rate updated, a regulation changed — it does not affect this transaction. It will affect the next one, which runs a fresh pipeline.


THE HS CODE CORRECTION EDGE CASE

There are real scenarios where a human reviewer changes the HS code entirely — for example, a product description like "wireless adapter" could be validly classified as WiFi equipment (8517.62), Bluetooth (8517.69), or a power adapter (8504.40), and the AI picks the wrong one. Or a product straddles two categories, like a smartwatch that could fall under watches (9102) or communication equipment (8517) depending on primary function.

When this happens, the duty rate and compliance status frozen in state were calculated for the wrong HS code and are now invalid. The fix is a conditional route on resume.

When the graph resumes at HumanReviewNode, it compares human_resolution.hs_code against the original hs_code in state and sets the hs_code_changed boolean accordingly. The node then has two outgoing edges: if hs_code_changed is false, it routes directly to ResultAssemblerNode using the frozen state. If hs_code_changed is true, it updates hs_code in state with the human's value and routes back to ComplianceCheckNode, which re-runs ComplianceCheckNode and DutyCalculatorNode with the corrected code before reaching ResultAssemblerNode.

The one determinism caveat with this path is that re-running those nodes means fetching from live sources. If a tariff changed during the pause, this transaction picks up the new rate. I'd argue that's the correct behaviour — if a human is correcting a fundamental classification error, assembling a result from stale data calculated for the wrong code is worse than running fresh lookups with the right one. Logic stays in the graph where it belongs, and the human review UI stays presentational.
